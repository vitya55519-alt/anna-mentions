# Коммент-сканер

Telegram Mini App и бот, которые собирают сообщения из чатов, кладут их в поисковый
индекс и помечают находки по статьям УК РФ с объяснением «почему».

**Сейчас основной режим — Telegram.** Бот читает чаты, куда его добавили, и ему не нужна
ни пользовательская сессия, ни токены других сетей. Адаптеры ВК, ОК и Instagram остаются
в коде: они включаются одной переменной `ENABLED_NETWORKS`, когда появятся токены.

Интерфейс повторяет референс: карточка = `статья · вердикт · оценка · дата`, текст в
кавычках, блок «почему», две ссылки — на конкретное сообщение и на сам чат («чат: Название»),
фильтры по статьям и сетям, выгрузка в CSV, команды `/find`, `/check`, `/art 205.2`, `/csv`.

## Что реально работает

| Сеть | Статус | Что нужно | Ограничение |
|---|---|---|---|
| Telegram (живой чат) | работает по умолчанию | только `BOT_TOKEN` | бот видит только новые сообщения, история не подтягивается |
| Telegram (группы аккаунтов) | опционально | `TG_API_ID`, `TG_API_HASH`, `TG_SESSION_1..3` | читает только то, что видят сами аккаунты; лимиты Telegram |
| Telegram (история одного канала) | опционально | `TG_API_ID`, `TG_API_HASH`, `TG_SESSION_STRING` | нужна сессия аккаунта: Bot API не отдаёт историю комментариев |
| ВКонтакте | в коде, выключен | `VK_TOKEN` + `ENABLED_NETWORKS=telegram,vk` | личные страницы не поддерживаются, только сообщества |
| Одноклассники | в коде, выключен | приложение OK + `OK_ACCESS_TOKEN` | комментарии доступны только внутри обсуждений группы |
| Instagram | в коде, выключен | — | Graph API отдаёт комментарии только ваших бизнес-медиа; скрапинг нарушает ToS |

Поиск идёт **только по источникам, которые вы сами подключили**. Это не глобальный поиск по
всему интернету — такого API не существует ни у одной из сетей.

## Как устроено

```
Telegram-чаты (бот добавлен в группу/канал)          Группы аккаунтов-сборщиков (MTProto)
        │  обновления Bot API → ingest                        │  /scan → discovery
        │                                                     ▼
        │                                        sources(ingest_mode=scan, cursor.account)
        ▼                                                     │
   worker: upsert в Postgres → проверка по статьям УК РФ (правила + LLM)
        │                                        │
        │                                        ├─→ уведомления в бота по словам
        ▼                                        ▼
   Postgres: posts, comments, tsv (GIN), verdict/score/rationale
        │
        ▼
   FastAPI: /api/search (FTS 'russian' + подсветка), /api/lookup, /api/sources, /api/sources/import, /api/stats
        │
        ├─→ Mini App (static/, тема Telegram)
        └─→ бот (aiogram): /find, /check, /art, /csv, /add, /stats, /scan, /acc
```

Три режима наполнения в поле `sources.ingest_mode`:

- `live` — бот сидит в чате и читает сообщения сразу;
- `scan` — группу читает один из привязанных аккаунтов по расписанию (поле `cursor.account`);
- `crawl` — плановый обход адаптером (ВК/ОК/MTProto).

Аккаунты-сборщики делят работу по группам: каждый аккаунт отдаёт свой список диалогов,
источник закрепляется за тем аккаунтом, который его нашёл. Если та же группа уже подключена
живьём, второй источник не создаётся.

Плановый обход (адаптеры ВК/ОК/MTProto) остаётся в воркере для источников с
`ingest_mode = crawl`; чаты, подключённые ботом, помечаются как `live` и планировщик их не трогает.

Скоринг двухступенчатый: сначала дешёвые правила из `rubrics/uk_rf.json` отсекают
кандидатов, затем LLM (любой OpenAI-совместимый эндпоинт) подтверждает статью и пишет
объяснение. Если LLM не настроен, всё работает на правилах.

## Классификатор статей УК РФ

Набор лежит в `rubrics/uk_rf.json` — обычный JSON, движок его просто читает.
Сейчас в наборе девять статей:

| Код | Что ловит |
|---|---|
| 205.2 | призывы к терроризму, оправдание и пропаганда терроризма |
| 207.3 | «фейки» об армии и госорганах |
| 280 | призывы к экстремизму, насильственной смене власти |
| 280.1 | призывы к нарушению территориальной целостности |
| 280.2 | отчуждение территории, пересмотр границ |
| 280.3 | дискредитация армии |
| 280.4 | призывы против безопасности государства |
| 282 | возбуждение ненависти и вражды |
| 354.1 | реабилитация нацизма |

Как считается оценка: у статьи есть `weight` (0…1), `patterns` (префиксы со звёздочкой)
и `phrases` (точные фразы). Сработавшие маркеры дают
`weight × (1 − 0.35^маркеров)`, дальше вердикт: `≥ 0.8` — **вероятно**,
`≥ 0.5` — **пограничное**, иначе — **не попадает**. В карточке видно, какие маркеры
сработали, какие статьи оказались ближайшими и почему выбран этот код. Если настроен LLM,
он перепроверяет выбор, может понизить вердикт до «пограничного» и объясняет, почему
соседние статьи не подходят.

**Это ориентир, а не квалификация.** Состав зависит от умысла, контекста и остальных
обстоятельств; решение принимает юрист. Об этом же написано в `/help` и в описании бота.

Добавить статью — это дописать объект в `categories`:

```json
{"code": "148", "title": "оскорбление чувств верующих", "description": "…",
 "weight": 0.85, "patterns": ["оскорбл*", "надругат*"], "phrases": ["оскорбить чувства"],
 "rationale_hint": "публичное оскорбление чувств верующих"}
```

После правки файла перезапустите сервис. `RUBRICS_FILE=default.json` возвращает старые
бытовые рубрики — на Railway должно стоять `uk_rf.json` (это значение по умолчанию).
Строки, размеченные до смены набора, сохраняют старые коды (`TERROR`, `INSULT` и т. п.):
они видны в фильтре, пока в базе есть такие комментарии. Переразметка —
`python scripts/reanalyze.py` (только старые коды и непроверенные строки), `--all` — всё
заново, `--no-llm` — без обращения к модели.

Поиск по статье: `/art 205.2` — находки только по ней (с порогом «пограничное» и выше),
`/find 205.2` — то же без порога, в приложении то же делает чип-фильтр, а выгрузка —
`/csv 205.2`.

## Поиск по списку: @ник, id, телефон

Вкладка «Список» принимает до 100 записей — по одной в строке, через запятую или
пробел — и показывает карточки по каждому значению отдельно. Тип выбирать не нужно, он
определяется по написанию:

| Что вставили | Что проверяем |
|---|---|
| `@ivan_petrov`, `ivan_petrov`, `t.me/ivan_petrov` | хвост `author_url` (`https://t.me/ivan_petrov`) и имя автора |
| `123456789`, `id123456789` | `comments.author_external_id` — Telegram id автора |
| `+7 999 123-45-67`, `8 999 123 45 67`, `89991234567` | последние 10 цифр в тексте сообщения и в имени автора |

Разбирать руками ничего не надо: телефон остаётся одной записью, даже если написан
с пробелами и скобками, а два числовых id в одной строке не склеиваются. Что не
удалось распознать, показывается отдельным блоком «не разобрал».

Найденное идёт сверху, записи без совпадений — компактным списком внизу. Чем длиннее
список, тем меньше карточек на запись сервер отдаёт (5 / 3 / 2) — общее число
совпадений при этом считается полностью. Если записей больше 100, проверяются первые
100, а сколько не влезло — написано в статусе.

Важно про телефон: Bot API не отдаёт номера чужих аккаунтов, MTProto — тоже. Номер
находится там, где он написан словами: в тексте сообщения или в имени. Если номер нигде
не встречается, поиск по нему ничего не вернёт.

Обычный поиск тоже понимает телефон: строка `+7 999 123-45-67` в поле поиска или в
`/find` ищет цифры в тексте, а не точное совпадение с пробелами и дефисами.

В боте то же самое делает `/check`:

```
/check @ivan_petrov, 123456789, +7 999 123-45-67
```

Список можно прислать несколькими строками: команда принимает многострочный текст до
100 записей. В ответе — сколько всего записей и совпадений, первые находки и список
записей без совпадений; полный результат открывается в приложении.

Поиск по цифрам в тексте идёт без индекса (`regexp_replace` по `comments.text`): на
десятках тысяч строк это заметно, при необходимости добавляется колонка с очищенными
цифрами и обычный индекс.

## Локальный запуск

Нужен Python 3.11+ и Postgres. Без Docker проще всего взять Postgres на Railway и
скопировать оттуда `DATABASE_URL`.

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
Copy-Item .env.example .env
```

В `.env` достаточно задать `DATABASE_URL`, `BOT_TOKEN` и `DEV_MODE=true`. Токены ВК/ОК
не нужны: по умолчанию `ENABLED_NETWORKS=telegram`. Затем в двух терминалах:

```powershell
uvicorn app.main:app --reload --port 8080
python -m app.worker
```

Приложение: `http://localhost:8080` (в dev-режиме авторизация Telegram не проверяется).

Локальный LLM (по желанию): `LLM_BASE_URL=http://127.0.0.1:11434/v1`, `LLM_MODEL=qwen2.5:7b`.

| `WEBAPP_URL` | HTTPS-адрес сервиса; он же URL Mini App и кнопки меню |
| `RAILWAY_PUBLIC_DOMAIN` | домен от Railway; если `WEBAPP_URL` пуст, адрес собирается из него |
| `DATABASE_URL` | Railway подставляет сам при линковке Postgres |
| `ENABLED_NETWORKS` | какие сети видны в приложении; по умолчанию `telegram` |
| `TG_LIVE_INGEST` | читать сообщения из чатов, куда добавлен бот (по умолчанию включено) |
| `VK_TOKEN` / `VK_USER_TOKEN` | доступ к API ВК (нужно добавить `vk` в `ENABLED_NETWORKS`) |
| `TG_API_ID`, `TG_API_HASH`, `TG_SESSION_1..5` | аккаунты-сборщики: поиск по всем их группам и каналам |
| `TG_SESSION_STRING` | старое имя для одной сессии (тоже подхватывается) |
| `TG_SCAN_DIALOGS_LIMIT`, `TG_SCAN_MESSAGES_PER_DIALOG` | сколько диалогов брать у аккаунта и как глубоко читать |

| `JOIN_PAUSE_SECONDS`, `JOIN_RETRY_MINUTES` | пауза между вступлениями (45 с) и повтор временной ошибки (60 мин) |
| `JOIN_QUEUE_LIMIT`, `JOIN_DISCUSSION_GROUPS` | сколько ссылок держать в очереди (2000) и вступать ли в привязанную группу обсуждения (да) |
| `OWNER_TELEGRAM_ID` | кому принадлежат найденные группы (0 — первый, кто написал боту) |
| `OK_APP_KEY`, `OK_APP_SECRET`, `OK_ACCESS_TOKEN`, `OK_ADAPTER_ENABLED` | бета-адаптер ОК |
| `RUBRICS_FILE` | какой набор статей использовать (по умолчанию `uk_rf.json`) |
| `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL` | второй проход проверки |
| `APP_ROLE` | `web` или `worker` — какой процесс поднимать в контейнере |
| `DEV_MODE` | **только локально**: отключает проверку `initData` |

## Подключение чата

1. Откройте приложение → «Источники» → «Добавить» → «Добавить бота в чат».
2. Выберите группу или канал — бот напишет вам, что чат подключён.
3. Напишите сообщение в чат: оно появится в ленте и пройдёт проверку по рубрикам.

Для групп выключите боту Privacy Mode в @BotFather (Bot Settings → Group Privacy) или
сделайте его администратором. Для каналов бот обязан быть администратором — иначе он не
увидит посты.

**Группы трёх аккаунтов.** Если нужно искать не только в чатах, куда добавлен бот, а во всех
группах ваших аккаунтов, привяжите их сессии:

```powershell
python scripts/tg_session.py
```

Скрипт по очереди входит в аккаунты и выдаёт строки `TG_SESSION_1`, `TG_SESSION_2`,
`TG_SESSION_3` — до пяти. Добавьте их в переменные Railway вместе с `TG_API_ID` и
`TG_API_HASH`, перезапустите worker и отправьте боту `/scan`: он обойдёт диалоги всех
аккаунтов, заведёт на каждую группу или канал источник и поставит их в очередь.

Настройки обхода: `TG_SCAN_DIALOGS_LIMIT` (сколько групп и каналов брать у аккаунта, 100),
`TG_SCAN_MESSAGES_PER_DIALOG` (глубина первого прохода, 120), `TG_SCAN_INTERVAL_MINUTES`
(как часто искать новые группы, 60) и `TG_SCAN_CHANNELS` (сканировать ли каналы).
Первый проход по большой базе групп идёт долго и упирается в лимиты Telegram —
дальше каждый обход читает только новые сообщения.

`/acc` показывает, сколько аккаунтов на связи и сколько групп уже в базе. Строка сессии
даёт полный доступ к аккаунту — держите её только в переменных Railway, не в репозитории.

**Массовое подключение.** «Источники» → «Массовое подключение»: вставьте ссылки
`t.me/…` по одной в строке и нажмите «Поставить в очередь». Подойдут публичные ссылки
`t.me/name`, ссылки на посты `t.me/name/123`, юзернеймы `@name` и приглашения
`t.me/+hash` / `t.me/joinchat/hash`.

Очередь обрабатывает worker, по одному вступлению за подход:

- аккаунт выбирается с наименьшей нагрузкой, квота — `JOIN_DAILY_LIMIT` слотов на аккаунт в сутки;
- между вступлениями пауза `JOIN_PAUSE_SECONDS`, на `FloodWait` аккаунт засыпает на срок лимита;
- после вступления сразу создаётся источник `scan` и ставится в очередь на чтение;
- если у канала есть привязанная группа обсуждения, очередь пробует вступить и в неё и
  завести второй источник: комментарии к постам канала лежат именно там;
- канал занимает один слот квоты, канал вместе с новой группой — два;
- «уже был» — аккаунт уже состоял в чате, источник просто подключён;
- ошибки видны в списке; ссылку можно вставить ещё раз, чтобы повторить.

Канал и его комментарии — разные чаты. Автоподключение группы работает по возможности:
закрытую группу или группу с заявками нужно добавить отдельной ссылкой-приглашением.
Отключить попытки можно через `JOIN_DISCUSSION_GROUPS=false`.
Лимит Telegram — около 500 групп и каналов на аккаунт, поэтому три аккаунта дают примерно
1500 источников; очередь не пытается обойти этот лимит, а распределяет ссылки по аккаунтам.

**ВК, ОК, Instagram.** Адаптеры лежат в `app/adapters/` и готовы к работе, но выключены:
добавьте сеть в `ENABLED_NETWORKS` и заполните токены. Для ВК нужен токен пользователя
со scope `wall` (сервисный ключ не подходит для `newsfeed.search`); для ОК — приложение
на `apiok.ru` и токен с доступом к группе; Instagram по-прежнему недоступен — у Meta нет
публичного API глобального поиска комментариев.

## Как ищет

Запрос проходит три шага: разбор → отбор → порядок выдачи.

**Разбор.** Строка обрезается до 200 символов и разбирается на слова. Специальные формы
уходят в отдельные условия, а не в полнотекстовый индекс:

- `@ivan_petrov` — по ссылке на профиль и по имени автора, без учёта регистра;
- `123456789` — точный Telegram id автора, номер статьи и вхождения в текст/имя;
- `205.2` — только находки по этой статье;
- `+7 (999) 123-45-67` — по цифрам номера в тексте комментария.

**Отбор.** Обычные слова ищутся одновременно двумя способами: полнотекстовый индекс
`russian` с префиксами (`блокир` → `блокировка`, `блокировки`, `блокировкой`) и подстрока
`ILIKE` (ловит то, что морфология пропустила). Несколько слов по умолчанию обязаны
встретиться все: `блокировка кремль` → `'блокировка':* & 'кремль':*`. Фраза в кавычках
требует соседства слов (`<->`). Если по всем словам пусто, срабатывает запасной вариант
через «или»: выдача помечается «точных нет, показаны по отдельным словам».

**Порядок.** В Mini App по умолчанию — по точности: `ts_rank_cd` (учитывает близость слов),
затем дата и id. Кнопка «сортировка» переключает на «сначала новые»; `/find` в боте тоже
сортирует по точности, а CSV выгружается в хронологии. Сниппет приходит с подсветкой
`<mark>`; Mini App её рисует, бот срезает.

**Скорость.** При старте приложение включает `pg_trgm` и создаёт GIN-индексы по `text`,
`author_name`, `author_url` — иначе `ILIKE '%...%'` читал бы всю таблицу. Если у роли базы
нет прав на `CREATE EXTENSION`, приложение продолжает работать: в лог пишется
предупреждение, поиск просто медленнее. Индексы создаются один раз, первый старт на
большой базе может занять несколько секунд.

Самопроверка без базы данных:

```powershell
python scripts/selftest.py
```

## Рубрики

`rubrics/default.json` — обычный JSON: `code`, `title`, `description`, `weight`,
`patterns` (префиксы, `взорв*`), `phrases`, `rationale_hint`. Коды можно заменить на свои
внутренние обозначения — движок от них не зависит.

Правила дают оценку `weight * (1 - 0.35^маркеров)`; `>= 0.8` — «вероятно», `>= 0.5` —
«пограничное». LLM вызывается только для кандидатов выше `LLM_MIN_SCORE`, чтобы не платить
за каждый комментарий.

## Тестовый запуск на Railway

1. Запушьте репозиторий на GitHub и создайте проект из него (или обновите существующий).
2. Добавьте **Postgres** — переменная `DATABASE_URL` появится в сервисах автоматически.
   Если база осталась от прошлой версии, сначала выполните SQL из раздела
   «Обновление со старой версии».
3. Сервис `web`: `APP_ROLE=web`, `BOT_TOKEN`, `ENABLED_NETWORKS=telegram`.
   В Settings → Networking нажмите **Generate Domain** — получится адрес вида
   `https://имя.up.railway.app`, он и есть адрес Mini App.
4. Продублируйте сервис (`Duplicate`) и назовите `worker`: `APP_ROLE=worker`.
   **Реплики = 1**: бот работает через polling, два процесса конфликтуют в Telegram.
   Healthcheck воркеру не нужен — у него нет HTTP-порта.
5. Впишите адрес из шага 3 в `WEBAPP_URL` **обоих** сервисов и перезапустите их.
6. В логах worker должно появиться «Бот подключён, команды доступны».

`RAILWAY_PUBLIC_DOMAIN` платформа выставляет сама, и адрес собирается без ручной
настройки — но только у сервиса с доменом. Поэтому шаг 5 лучше не пропускать.

### Кнопка приложения

Отдельно в BotFather ничего настраивать не нужно: при старте web и worker сами ставят
кнопку меню (`set_chat_menu_button`) на адрес из `WEBAPP_URL`.

- **Кнопка меню** — слева от поля ввода в личке с ботом, открывает Mini App.
- **`/app`** — присылает ту же кнопку сообщением, если меню не обновилось.
- **`/start`** — приветствие с кнопкой «Открыть сканер».

Адрес приложения нельзя открывать в браузере: Mini App запускается только изнутри
Telegram, иначе `initData` пустой и API ответит 401. `/setmenubutton` в BotFather тоже
работает, но его значение перезапишется при следующем рестарте сервиса.

### Проверка

`/diag` — адрес приложения, связь с базой, число источников и аккаунтов.
Дальше: добавьте бота в тестовую группу, напишите сообщение, откройте приложение.

После добавления бота в чат ничего жать не нужно: сообщения приходят в ленту сами. Кнопка
«Обновить» есть только у источников с плановым обходом (ВК/ОК/MTProto).

## Обновление со старой версии

Предыдущая версия приложения создавала таблицу `comments` с другой структурой. `create_all`
существующие таблицы не меняет, поэтому старую таблицу надо удалить один раз — в Railway
откройте Postgres → Query и выполните:

```sql
DROP TABLE IF EXISTS comments, posts, sources, watches, crawl_runs, users CASCADE;
```

После перезапуска сервис создаст схему заново. Если в таблице не окажется колонки `verdict`,
приложение остановится с этим текстом в логах вместо непонятных ошибок.

## Ограничения и правовые заметки

- Рубрики и оценки — сигнал для проверки человеком, а не юридическое заключение.
- Инструмент для модерации и мониторинга публичных комментариев; не собирайте досье на
  людей и не используйте его как повод для доносов.
- VK и OK ограничивают частоту запросов: обход идёт порциями, ошибки видны в карточке
  источника, при сбое включается бэкофф 15 минут.
- `initData` проверяется по HMAC-SHA256 от `BOT_TOKEN`; срок жизни — 24 часа.
- Скрипт `telegram-web-app.js` грузится с `telegram.org` — это официальный источник, но
  внешний; при желании положите его копию в `static/`.
